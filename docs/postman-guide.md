# Проверка AutoStart через Postman

Коллекция находится в [AutoStart.postman_collection.json](AutoStart.postman_collection.json). Перечень маршрутов и полей приведён в [спецификации API](api.md), установка приложения и локальные аккаунты описаны в [README](../README.md).

## Подготовка

1. Запустите Laravel и MySQL одним из способов из README.
2. Для полного прогона подготовьте отдельную локальную базу с начальным наполнением. Запросы коллекции создают пользователей, подают заявки, бронируют и отменяют занятия, а также изменяют тестовые записи справочников.
3. Импортируйте JSON-файл в Postman.
4. В переменных коллекции задайте `base_url` для выбранного способа запуска.

| Способ запуска | Значение `base_url` |
| --- | --- |
| OSPanel | `http://autoschool.loc/api` |
| `php artisan serve --host=127.0.0.1 --port=8000` | `http://127.0.0.1:8000/api` |

Не добавляйте завершающий `/`: он уже есть в адресах запросов коллекции. Если нужно проверить существующую базу, выбирайте отдельные запросы и учитывайте состояние её записей.

## Авторизация и переменные

Сначала выполните запрос «Соединение с MySQL» в папке «Публичная часть». Ожидается HTTP 200 с полем `"database": "ok"`. Ответ 503 означает, что нужно проверить MySQL и параметры подключения в `.env`.

Далее выполните папку «Аккаунты» по порядку. Запросы входа используют локальные аккаунты из README и сохраняют токены в переменные. Регистрация создаёт отдельного курсанта для дальнейшего сценария.

| Переменная | Для чего нужна |
| --- | --- |
| `base_url` | Адрес API текущего экземпляра приложения |
| `admin_token` | Запросы администратора |
| `instructor_token` | Запросы инструктора |
| `student_token` | Запросы курсанта |
| `token` | Общий токен для запросов, наследующих авторизацию коллекции |
| `student_id`, `group_id`, `enrollment_id` | Пользователь, выбранная группа и заявка |
| `slot_id`, `car_id`, `new_slot_id`, `past_slot_id` | Записи для сценариев практики |
| `ticket_version`, `ticket_answers`, `attempt_id` | Данные билета и сохранённой попытки |

Скрипты после успешных ответов подставляют идентификаторы для следующих запросов. У запросов разных ролей явно настроены нужные Bearer-токены. При ручном создании запроса добавьте `Accept: application/json`, для JSON-тела также `Content-Type: application/json`, а в авторизации выберите Bearer Token нужного пользователя.

Сами токены берутся из ответа входа; отправлять пароль вместо токена нельзя. Если сеанс закончился или токен отозван, повторите вход соответствующей роли.

## Порядок полного прогона

| Папка | Что проверяется |
| --- | --- |
| Публичная часть | Связь с MySQL, программы, отказ в доступе к профилю без токена |
| Аккаунты | Вход каждой роли, регистрация курсанта, профиль и ограничения доступа |
| Заявка и бронирование | Выбор группы, подача заявки, зачисление, запись и отмена практики |
| Кабинет инструктора | Просмотр занятий, создание и изменение слота, отмена, завершение и часы |
| Экзамены ПДД | Получение билета, сдача ответов, история и разбор попытки |
| Управление | Создание, чтение, изменение и удаление записей справочников |
| Платежи и отчёты | Внесение и исправление взноса, баланс, сводка и отчёт по инструкторам |

Сохраняйте этот порядок и порядок запросов внутри папок: последующие шаги используют результаты предыдущих. После выполнения просматривайте HTTP-статус, тело ответа и результаты встроенных проверок коллекции.

## Зачисление и бронирование по шагам

| Запрос коллекции | Ожидаемый результат |
| --- | --- |
| Набор в группы B | 200; выбрана открытая группа, сохранён `group_id` |
| Подать заявку | 201; создана заявка, сохранён `enrollment_id` |
| Мои заявки | 200; курсант видит свою заявку |
| Ожидающие заявки | 200; администратор получает заявки на рассмотрении |
| Зачислить курсанта | 200; статус участия изменён на `approved` |
| Свободное вождение | 200; найдены будущие занятия подходящей категории |
| Забронировать | 200; выбранное занятие связано с курсантом и имеет статус `booked` |
| Повторное бронирование | 409; повторная запись на тот же слот отклонена |
| Карточка записи | 200; сохранённые данные занятия доступны текущему курсанту |
| Освободить слот | 200; запись курсанта отменена, занятие снова свободно |

При ручном выполнении можно использовать реальные идентификаторы из ответов вместо переменных коллекции. В запрос бронирования не требуется передавать `student_id`: пользователь определяется по токену.

Если группа заполнена, набор закрыт или занятия пересекаются, бизнес-сценарий вернёт 409. Это ожидаемое ограничение приложения. Для продолжения выберите подходящие исходные данные.

В папке инструктора запрос «Найти прошедшее занятие» выбирает забронированную практику, время которой уже закончилось. Именно её можно отметить проведённой. Созданный будущий слот сразу завершить нельзя. Количество часов проверяется запросами «Часы курсанта» и «Часы инструктора».

## Билеты и списки

Для экзамена сначала запросите билет, затем отправьте ответы с его текущей `version`. Коллекция переносит подготовленные данные в переменные. При изменении вопросов во время прохождения загрузите билет заново. Результат сохраняется как отдельная попытка; доступен запрос её разбора.

Для проверки поиска, сортировки и пагинации отправьте запрос от администратора:

```http
GET {{base_url}}/users?role=student&sort=name&order=asc&page=1&per_page=5
```

Ответ списка содержит `data`, `links` и `meta`. Проверьте размер страницы `per_page`, текущую страницу `current_page` и количество записей `total`. Для поиска добавьте `search`, для другого порядка измените `order`. Недопустимое поле `sort` или размер страницы больше 100 дают ошибку валидации 422.

## Разбор ошибок

| Код | Что проверить |
| --- | --- |
| 401 | Токен отсутствует, истёк или отозван; повторите вход |
| 403 | Выбрана нужная роль и пользователю принадлежит проверяемая запись |
| 404 | Идентификатор существует в текущей базе, переменная заполнена |
| 409 | Состояние заявки или занятия, время, вместимость, пересечения |
| 422 | Поля объекта `errors`, обязательные значения и формат дат |
| 429 | Частота входа и регистрации; дождитесь окончания ограничения |
| 503 на `/health` | Запуск MySQL и параметры `DB_*` |

Неудачное зачисление или отсутствие свободных слотов может зависеть от уже сохранённых данных и дат. Для повторного полного прогона используйте новый начальный набор в выделенной базе. `migrate:fresh --seed` полностью пересоздаёт выбранную схему; порядок подготовки тестовой базы приведён в README.
