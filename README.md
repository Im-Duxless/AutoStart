# AutoStart

AutoStart ведёт набор в группы автошколы, расписание теории и вождения, тренажёр ПДД и учёт платежей. Vue-клиент и Laravel REST API находятся в одном репозитории. При отдельном запуске для разработки они используют разные порты.

## Возможности

| Пользователь | Основные действия |
| --- | --- |
| Курсант | Заявка в группу, расписание, запись на вождение, часы практики, билеты ПДД и свои платежи |
| Инструктор | Создание свободного времени, просмотр своих курсантов, завершение занятий и учёт часов |
| Администратор | Зачисление, пользователи, группы, транспорт, занятия, вопросы, платежи и отчёты |

Публичная регистрация создаёт курсанта. Права инструктора и администратора назначаются через административный кабинет.

## Установка после клонирования

```powershell
git clone https://github.com/Im-Duxless/AutoStart.git
Set-Location AutoStart
```

Все следующие команды выполняются из корня репозитория, где находится файл `artisan`, если явно не указан другой каталог.

Порядок первой установки: установить зависимости, настроить `.env`, создать базу MySQL, выполнить миграции с сидерами, затем запустить сервер и клиент. Для OSPanel готовый клиент собирается в `public/client`.

## Запуск через OSPanel

Для локального домена `autoschool.loc` включите проект в OSPanel. В меню выберите `autoschool.loc` → «Включить модули проекта», затем «Открыть в браузере». Apache раздаёт сборку Vue и передаёт запросы `/api/*` Laravel. Для открытия сайта достаточно Apache, PHP 8.3 и MySQL 8.0 из OSPanel. [Открыть AutoStart через OSPanel](http://autoschool.loc/)

Настройки проекта находятся в `.osp/project.ini` каталога, зарегистрированного в OSPanel. Команда `osp project autoschool.loc` в консоли OSPanel открывает рабочую папку этого проекта. Для коллекции Postman задайте `base_url=http://autoschool.loc/api`.

После изменения интерфейса пересоберите его из корня проекта.

```powershell
npm.cmd --prefix client run build:ospanel
```

Для настройки на другом компьютере поместите проект в каталог `home/autoschool.loc` OSPanel 6.5 и создайте в нём файл `.osp/project.ini`.

```ini
[autoschool.loc]
http_engine = Apache
php_engine = PHP-8.3
environment = MySQL-8.0
web_root = {project_root}\public
tls_enabled = off
```

Перезапустите OSPanel, включите модули проекта и настройте `.env` на свою базу MySQL. Значения `DB_HOST` и `DB_PORT` возьмите из настроек включённого модуля: у OSPanel адрес MySQL может отличаться от `127.0.0.1`.

После установки Composer-зависимостей и настройки базы выполните из корня проекта:

```powershell
php artisan migrate --seed
npm.cmd --prefix client ci
npm.cmd --prefix client run build:ospanel
```

В `.env` задайте `APP_URL=http://autoschool.loc`. После изменения настроек выполните `php artisan config:clear`. Для этого режима не требуется запускать `artisan serve` или Vite отдельно: страницу открывают по адресу `http://autoschool.loc/`. [Документация Open Server Panel](https://github.com/OSPanel/OpenServerPanel/wiki#creating-projects)

Для проверки откройте [http://autoschool.loc/api/health](http://autoschool.loc/api/health). HTTP 200 и поле `"database": "ok"` подтверждают связь Laravel с настроенной базой. Сначала проверьте этот адрес, затем вход в кабинет.

| Что происходит | Что проверить |
| --- | --- |
| Домен `autoschool.loc` не находится | Проект добавлен в OSPanel, его модули включены; после изменения конфигурации OSPanel перезапущен |
| `/api/health` возвращает 503 | MySQL запущен, база создана, реквизиты `DB_*` соответствуют выбранному модулю |
| Страница открывается, но изменения интерфейса не появились | Выполнена сборка `npm.cmd --prefix client run build:ospanel`, затем страница перезагружена |
| PHP или Composer не найдены в обычном терминале | Открыта консоль OSPanel либо путь к PHP добавлен в текущий `Path` |

## Что установить

- PHP 8.3 или новее с расширениями `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `curl`, `dom` и `xml`. Для запуска тестов без MySQL нужен `pdo_sqlite`.
- Composer 2, MySQL 8.0 или 8.4 и Node.js 20.19+ либо 22.12+.
- OSPanel подходит для запуска PHP и MySQL в Windows. VS Code и Postman удобны для работы с кодом и проверки API.

Проверьте версии командами `php -v`, `composer --version` и `node -v`. Если PHP есть только в OSPanel, откройте его терминал или добавьте каталог нужного PHP в `Path` текущего PowerShell. В стандартной установке Composer доступен как PHAR.

```powershell
$env:Path = 'C:\OSPanel\modules\PHP-8.3;' + $env:Path
php C:\OSPanel\data\PHP-8.3\default\composer\composer.phar --version
```

Если команда `composer` не найдена, используйте тот же путь к PHAR для команды `install` ниже.

## Сервер и база данных

1. Запустите модуль MySQL в OSPanel. Адрес, порт и пользователя возьмите из настроек запущенного профиля MySQL.
2. В консоли MySQL или в менеджере БД создайте отдельную базу приложения.

```sql
CREATE DATABASE autostart CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

3. В корне проекта установите зависимости и создайте локальную конфигурацию.

```powershell
composer install
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item .env.example .env
    php artisan key:generate
}
```

Если файл `.env` уже настроен, используйте его. Если у него пустой `APP_KEY`, создайте ключ командой `php artisan key:generate`. Проверьте параметры подключения к своей базе; значения ниже соответствуют обычному локальному MySQL на порту `3306`.

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=autostart
DB_USERNAME=root
DB_PASSWORD=
```

Имя пользователя и пароль должны соответствовать настройкам вашего MySQL. После изменения `.env` выполните `php artisan config:clear`. Для первоначального наполнения используется `APP_ENV=local` из `.env.example`.

4. Заполните новую базу и запустите Laravel.

```powershell
php artisan migrate --seed
php artisan serve --host=127.0.0.1 --port=8000
```

Проверка подключения к базе доступна по [адресу /api/health](http://127.0.0.1:8000/api/health). Если Symfony сообщает об ошибке доступа к временному каталогу OSPanel, укажите PHP каталог проекта.

```powershell
New-Item -ItemType Directory -Force work | Out-Null
php -d "sys_temp_dir=$($PWD.Path)\work" artisan serve --host=127.0.0.1 --port=8000
```

Для полного пересоздания **выделенной локальной базы** выполните `php artisan migrate:fresh --seed`. Команда удаляет все таблицы в выбранной базе.

## Клиент Vue

Откройте второй терминал в корне проекта.

```powershell
Set-Location client
npm ci
npm run dev
```

Откройте [AutoStart](http://localhost:5173). Для сборки используйте `npm run build`. Готовые файлы появятся в `client/dist`. Статический сервер должен отдавать `index.html` для маршрутов Vue Router.

По умолчанию браузер обращается к `http://127.0.0.1:8000/api`. Если меняете адрес API, скопируйте `client/.env.example` в `client/.env.local` и задайте `VITE_API_URL`. В Laravel укажите точный адрес клиента в `CLIENT_URL` и перезапустите оба приложения.

## Локальные аккаунты

Эти пароли предназначены для локальной проверки после запуска сидеров.

| Роль | Электронная почта | Пароль |
| --- | --- | --- |
| Администратор | `admin@autostart.local` | `AutoStart!2026` |
| Инструктор | `instructor@autostart.local` | `AutoStart!2026` |
| Курсант | `student@autostart.local` | `AutoStart!2026` |

Сидеры добавляют локальные данные в окружениях `local` и `testing`. Для нового наполнения используются даты относительно дня запуска. У готового курсанта подтверждена группа B. У инструктора есть проведённое вождение, предстоящие слоты и прошедшее занятие, которое можно отметить проведённым.

Повторный `db:seed` не обновляет даты уже созданного набора, если начальный администратор существует. Если сохранённые слоты оказались в прошлом, добавьте новые через кабинеты инструктора или администратора. Для демонстрации завершения используйте уже прошедшее забронированное занятие: будущую практику завершить нельзя.

Поля `SCHOOL_PHONE`, `SCHOOL_EMAIL`, `SCHOOL_ADDRESS` и `SCHOOL_HOURS` заполняются фактическими контактами школы. При пустых полях на странице доступна подача заявки через кабинет. Валюта и часовой пояс задаются в `SCHOOL_CURRENCY` и `APP_TIMEZONE`. Занятия вводятся и показываются по местному времени школы. Фотография на главной сгенерирована для оформления сайта. Билеты содержат авторские тренировочные вопросы.

## Проверка сценария

1. Зарегистрируйте нового курсанта, откройте «Обучение» и подайте заявку в открытую группу B.
2. В кабинете администратора откройте «Заявки» и зачислите курсанта. Во вкладке «Занятия» можно добавить теорию для этой группы.
3. Войдите курсантом и проверьте группу в расписании. На странице «Вождение» выберите время и подтвердите запись.
4. После окончания занятия инструктор открывает его из раздела «Мои занятия» и отмечает проведённым. Для быстрой ручной проверки можно завершить уже прошедшее занятие у локального инструктора.
5. Откройте «Экзамены ПДД», решите билет и проверьте сохранённый разбор.
6. В кабинете курсанта откройте «Оплата». В локальной форме «Демо-оплата» операция картой сразу меняет учтённую сумму. При выборе наличных создаётся заявка. Войдите администратором, откройте «Платежи» и подтвердите взнос. Курсант также может отменить ожидающую заявку. Банковский сервис не подключён; форма моделирует запись платежа без реального списания.

Для проверки разных ролей используйте отдельные профили браузера. Обычные вкладки одного профиля используют общий токен входа.

```powershell
php artisan route:list --path=api
php artisan test
```

По умолчанию PHPUnit запускает тесты на временной SQLite в памяти. Для той же проверки на MySQL используйте отдельную пустую схему. Пример в PowerShell ниже использует остальные реквизиты MySQL из `.env`. PHPUnit пересоздаёт таблицы в указанной тестовой схеме.

```sql
CREATE DATABASE autostart_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```powershell
$env:DB_CONNECTION = 'mysql'
$env:DB_DATABASE = 'autostart_test'
php artisan test
Remove-Item Env:DB_CONNECTION, Env:DB_DATABASE
```

## Где искать код

| `routes/api.php` | Маршруты и допуски по ролям |

| `tests/Feature` | Проверки сценариев через HTTP-интерфейс Laravel |
